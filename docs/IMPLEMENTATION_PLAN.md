# Deep Overhaul Implementation Plan

Prioritization is by expected project-value gain divided by implementation and regression risk.

## P0 — must complete before stronger claims

1. **Proof semantics:** separate minimum proof completeness from full landscape exhaustiveness.
2. **Certificate binding:** bind direction and selected candidate to the issued artifact; never issue the canonical artifact for a different request.
3. **Deep certificate replay:** recompute source summaries, audit rows, sufficiency, co-minimums, and witness experiment from engine inputs.
4. **Selection language:** label pointwise bootstrap as fixed-subset sensitivity and add a simultaneous finite-family analysis before confidence-qualified witness claims.
5. **Executed branch gate:** add CI and verify every milestone remotely.

## P1 — highest-value research upgrades

1. Add a generic finite protocol schema and exact substitution invariant.
2. Add exact cardinality-first and full-landscape algorithms with explicit guarantees and instrumentation.
3. Build a deterministic reconciliation benchmark independent of the canonical simulator.
4. Add bidirectional reconciliation and effect-restoration diagnostics.
5. Add versioned reconciliation artifact schemas and a standalone verifier entry point.
6. Update WebMCP lifecycle and current argument/output contracts.
7. Reposition the README and claims around a serious prototype rather than a contest demo.

## P2 — valuable strengthening

1. Add discordant-pair counts and exact two-sided McNemar/binomial p-values.
2. Add safe scaling experiments at `|H| = 4, 8, 12, 16`, avoiding explosive full simulation.
3. Add property tests for order invariance, co-minimum completeness, non-monotonicity, and exact substitution.
4. Add deterministic trace fixtures for current WebMCP schemas and explicit pending fields for real-agent trials.
5. Add browser-tool size limits, untrusted-data markers, and stale-state tests.

## P3 — polish after scientific green state

1. Simplify the UI around Dispute / Investigation / Evidence / Reconciliation / Certificate.
2. Archive hackathon phase history and remove obsolete “locked” wording.
3. Improve responsive visual hierarchy and accessibility.

## Milestone commit plan

1. `research: establish deep audit and formal model`
2. `refactor: add generic reconciliation core and proof semantics`
3. `test: add reconciliation benchmark and scaling instrumentation`
4. `fix: bind and replay reconciliation certificates`
5. `fix: add selection-aware statistical diagnostics`
6. `refactor: harden WebMCP lifecycle and agent evaluation contracts`
7. `docs: reposition MPW as a serious research prototype`

Commit names may change to reflect the actual completed work. A milestone is committed only when its available execution gate is green.
