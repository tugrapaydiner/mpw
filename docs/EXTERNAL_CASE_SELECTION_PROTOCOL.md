# External Evaluation-Dispute Case Selection Protocol

## Purpose

A reconciliation system can look artificially successful if external cases are chosen only after their witness landscapes are inspected. This protocol defines how future real-world MPW studies should identify and freeze candidate disputes before running the reconciler.

The protocol is intended for confirmatory case-series work. Exploratory examples may still be used for debugging, but they must be labeled and excluded from confirmatory success rates.

## Target population

The target population is publicly inspectable evaluation comparisons in which:

- two reports or configurations compare the same named systems or model pair;
- the evaluated task set or benchmark can be aligned with defensible evidence;
- the source conclusions are incompatible under a predeclared categorical rule;
- at least one protocol difference is documented or reconstructable;
- controlled hybrid configurations are already available or can be rerun legally and technically.

The study unit is a **dispute**, not an individual protocol row.

## Search frame

Before screening begins, register:

- databases, repositories, benchmark leaderboards, and proceedings to search;
- date range;
- search terms;
- supported languages;
- model and benchmark eligibility rules;
- whether preprints are included;
- whether duplicate versions of the same study are collapsed;
- the screening cutoff date.

Preserve the complete search result list or a content-addressed export when permitted. A narrative claim that “many papers were checked” is not sufficient.

## Inclusion criteria

A candidate is included when all of the following are established before reconciliation:

1. **Endpoint identity:** the two endpoint reports and their model identities are unambiguous.
2. **Benchmark alignment:** item universe, task set, or documented aggregate scope is sufficiently aligned for the intended claim.
3. **Conclusion rule:** the rule mapping evidence to endpoint conclusions is explicit and can be applied consistently.
4. **Protocol schema:** exposed differences and their endpoint values are represented without consulting the desired witness.
5. **Hybrid evidence:** the complete endpoint-substitution cube is available for a static study, or an executable evaluator can generate it under a frozen plan.
6. **Provenance:** source location, version, retrieval date, license or usage basis, and content identity are recorded.
7. **Independence from MPW:** the source measurements were not generated by the canonical MPW simulator.

## Exclusion criteria

Exclude—and record the reason—when:

- the compared model or benchmark identities cannot be aligned;
- endpoint conclusions differ only because the authors use incompatible undefined terms;
- the protocol difference was inferred solely from the desired result;
- hybrid rows are selectively available and exact minimum recovery is nevertheless being claimed;
- source evidence is inaccessible or legally unusable;
- a later report merely republishes the same measurements;
- the categorical rule is chosen after inspecting which witness it produces;
- missing or failed runs are outcome-selectively discarded;
- the source contains only a claim with no inspectable evidence or rerun path.

Exclusion because a case has no witness, an inconclusive target, a large minimum, or an inconvenient interaction pattern is prohibited.

## Freezing procedure

For every included case, freeze before reconciliation:

- dispute ID;
- source URLs or repository revisions;
- endpoint protocols;
- finite coordinate schema;
- endpoint conclusion rule;
- exposed and deliberately omitted dimensions;
- static versus executable evidence mode;
- item/run handling policy;
- uncertainty procedure;
- primary direction or both directions;
- primary objective and any cost weights;
- expected computational budget;
- all planned secondary diagnostics.

Hash the frozen manifest. Amendments require a new version and a reason; the original remains available.

Ground-truth witnesses, when known from synthetic or constructed cases, remain hidden from the implementation under evaluation.

## Primary outcomes

Report at least:

- valid source reproduction;
- exact witness status: found, empty, none, incomplete, or invalid source;
- minimum cardinality;
- complete co-minimum witness count;
- evaluated and required subset counts;
- A-to-B and B-to-A results when both are in scope;
- categorical target reproduction;
- effect distance to the target;
- familywise or repeated-run uncertainty status where applicable;
- runtime and evaluation cost;
- all exclusion and failure reasons.

A success rate must use the frozen included denominator. Do not remove cases after seeing that reconciliation fails.

## Secondary classifications

Classify landscapes using rules fixed before analysis:

- unique versus co-minimum;
- monotone versus observed non-monotone;
- singleton, pair, or higher-order minimum;
- interaction-only versus cumulative/sequential effect;
- nuisance coordinates;
- redundant coordinates;
- no exposed witness;
- directionally asymmetric;
- pointwise versus robust witness disagreement.

The strict interaction rule must require both constituent singletons to preserve the base conclusion if that is the intended construct. A pair should not be called an irreducible interaction merely because neither singleton reaches the final target.

## Statistical policy

For static aggregate grids, conclusions are descriptive over the recorded rows unless the source provides a defensible sampling model.

For item-level fixed runs, state whether uncertainty is over items, runs, graders, or another unit. For searched families, pointwise intervals are not presented as post-selection guarantees.

For repeated stochastic evaluations, predeclare:

- number or stopping rule for runs;
- target-reproduction definition;
- handling of failures and missing runs;
- robustness threshold;
- familywise error level;
- whether target uncertainty is fixed or paired within run.

Pilot data used to choose these values must be separated from confirmatory data.

## Baselines

At minimum compare exact MPW verification with:

- one-coordinate-at-a-time attribution;
- greedy forward proposal;
- random proposal under a fixed evaluation budget;
- full grid enumeration where tractable.

Heuristics may reduce proposal cost but cannot receive global-minimum credit without the required exact certificate coverage.

## Reporting negative results

Publish:

- no-witness cases;
- invalid or unreproducible endpoints;
- criteria that pass only under one conclusion rule;
- strict-interaction failures;
- robust-witness failures despite deterministic success;
- cases exceeding the exact-search budget;
- source packages that fail integrity checks.

A negative case can expose missing dimensions, weak publication evidence, or an overly coarse conclusion rule. It is not automatically a system failure.

## Sensitivity analyses

Predeclare a limited set of scientifically meaningful alternatives, such as:

- categorical versus effect-matching sufficiency;
- pointwise versus simultaneous intervals;
- multiple robustness thresholds;
- alternative but defensible benchmark strata;
- inclusion/exclusion of coordinates with ambiguous alignment.

Do not enumerate arbitrary choices and report only the favorable specification. Publish the complete registered sensitivity family.

## Reproducibility package

For each case, provide when legally possible:

- frozen case manifest;
- source identities and checksums;
- protocol schema;
- static grid package or executable adapter;
- raw item/run outcomes or an immutable retrieval procedure;
- reconciliation certificate;
- software revision and environment;
- exact command transcript;
- exclusion/amendment log.

## Independence and review

A stronger study should use two roles:

- **case curator:** screens sources and freezes manifests without running reconciliation;
- **analysis runner:** executes the frozen plan without changing inclusion criteria.

At least a sample of cases should receive independent protocol-schema review. Disagreements about coordinate alignment are scientific uncertainty and should be preserved rather than silently resolved in favor of a smaller witness.

## Current project status

The existing five-candidate external fragility-grid study is a useful transfer test but is not a representative case series. It predates this full selection protocol and therefore does not support prevalence estimates.

Future claims about real-world frequency, typical witness size, interaction structure, or agent efficiency require a study conducted under this protocol or an explicitly justified successor.
